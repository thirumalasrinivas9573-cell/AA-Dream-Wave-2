SECTION 1 - FEATURE REQUIREMENTS
--------------------------------
1.1 Goal
Replace the direct "checkbox -> task completed" behavior with:
LEARNING -> EXAM -> CERTIFICATION -> (Resume Builder) -> TASK COMPLETED

1.2 Source of truth
The backend decides every stage, status, score, pass/fail, certificate and completion.
The frontend only displays backend state and requests transitions.
The client must never send or compute stage, status, score, passed, completed or certificate flags.

1.3 Workflow vs legacy tasks
- Each task has a backend flag `workflowEnabled`.
- true  -> show the three-stage UI (Learning, Exam, Certification).
- false -> legacy task, old behavior and old UI unchanged.
- The flag is set by the backend only (auto-enable at creation by a server rule, or an explicit opt-in endpoint).

1.4 Learning stage
- Learning is satisfied by server-verified requirements: focus time on the task, subtasks completed, checklist completed.
- The UI shows which requirements remain.
- Learning opens the task's focus timer / subtasks / checklist (the /student/learn page has no task context).

1.5 Exam stage
- Locked until the backend verifies learning. The UI shows why it is locked.
- Questions come from the backend. Correct answers and explanations are not sent before submit.
- The backend scores the exam. The minimum passing percentage comes from the backend and is never hardcoded in the client.
- FAIL: the task goes back to Learning. Extra learning effort is required before another attempt.
- PASS: Certification starts.

1.6 Certification stage
- Never manually toggled by the user.
- After a pass the backend issues the certificate and shows a "generating" state while it works.
- The certificate is saved to the student profile credentials (no duplicates) and attached to one resume.
- If generation or linking fails, the exam result is kept and the user can retry.

1.7 Task completion
- The task becomes Completed only when the backend confirms the full workflow.
- Every other completion path is blocked for workflow tasks, including:
  checkbox, status selects (card, Kanban, edit form), progress slider reaching 100,
  StudyPlanner schedule complete, FocusMode "mark task complete",
  and any goal/agent completion path.
- Planner and focus endpoints still record the session but do not complete a workflow task.

1.8 State must survive a page refresh
The client always re-reads state from the backend (GET /api/tasks/:id/progression).

1.9 Legacy tasks and unrelated features must keep working.
